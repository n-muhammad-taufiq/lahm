## Change and test strategy

For each task, write and review a feature spec first: user flow, states, business rules, API/data contract, edge cases, accessibility, acceptance criteria and test plan. Only then implement in one-to-two-file steps (about 100 changed lines), reading full touched files/callers. Add tests alongside business logic/API contracts. After each step run the narrowest type/test check; at task completion run affected app/backend checks. This planning pass did not run tests; the host npm launcher currently fails to locate `npm-cli.js`, which must be resolved before verification claims.

Do not mark an ID complete based on a screen or compile alone. Record actual verification and unresolved edges in `CUSTOMER_APP_PROGRESS.md`; update the canonical roadmap only when owner-approved and acceptance criteria pass. Production-grade means real backend behavior, secured customer data, authoritative pricing/stock, COD and fulfillment integrity, loading/empty/error/offline handling, production configuration, and verified Android+iOS customer journeys. Deferred GST, serviceability, COD settlement or courier tracking cannot be silently omitted from launch readiness.
